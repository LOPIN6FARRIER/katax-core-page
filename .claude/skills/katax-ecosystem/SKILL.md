## Latest Practical Updates

- Prefer architecture: `validator -> controller -> handler -> routes`.
- Use shared `validateSchema` helper for consistent validation responses.
- Prefer typed repository access generated by CLI (`ISqlDatabase` / `IRedisDatabase`).
- `katax-cli init` defaults to `pnpm` and supports `--ignore-scripts` + `--write-npmrc`.
- Nested resources (e.g. `admin/users`) are supported by generators and should keep relative imports correct.
- Redis reconnect is built-in in modern `katax-service-manager`; only customize reconnect for external custom clients.
- Every katax-core schema has `toJsonSchema()` — bridges validators directly into JSON-Schema-consuming APIs (MCP tools, OpenAPI) without a second hand-written schema.

## Common Gotchas (cross-cutting, not tied to one package)

- ✅ Always call `katax.init()` before using any runtime service — `katax.db()`/`katax.ws()` before init throws `KataxNotInitializedError`.
- ✅ `dotenv.config()` must run before `katax` is imported, or use `katax.init({ loadEnv: true })` — katax reads env at import time otherwise.
- `required: false` on `katax.database()` → app continues if that connection fails; always null-check before use.
- Validate every request body with `.safeParse()`; use `coerce` schemas for query params (strings need converting to numbers/booleans).

See `references/production-hardening.md` for the full "house style" (rate limiting, CORS, cookies, sessions) and each package-specific reference file for its own gotchas section.
