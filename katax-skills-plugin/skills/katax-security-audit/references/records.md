# Run folder and record formats

## Run folder

Outside the repository, never inside it: findings are attack recipes, and a repository can be (or become) public.

```
~/.katax-audit/<repo-name>/run-<N>/
  ledger.json        units to cover (katax-routes.mjs), updated with every hunter's checks
  static-audit.txt   output of katax-audit.mjs (mechanical rules, not re-checked by hunters)
  architecture.md    trust boundaries, ≤ 60 lines (phase 1)
  hunt-<group>.json  one per hunter (phase 2)
  findings.json      validated records (phases 3-5)
  report.md          generated by katax-findings.mjs report (phase 6)
```

`<N>` is one more than the highest existing run. The next run starts with
`katax-findings.mjs carry <previous ledger> <new ledger>`.

## Unit (in ledger.json)

Written by `katax-routes.mjs`; hunters only change `status`, `checks` and `skipReason`.

```json
{
  "id": "PUT /api/workspaces/:id",
  "type": "endpoint",
  "resource": "workspace",
  "group": "workspace",
  "method": "PUT",
  "path": "/api/workspaces/:id",
  "file": "src/api/workspace/workspace.routes.ts", "line": 31,
  "middleware": [{ "name": "authenticate", "callee": "authenticate", "kind": "auth" }],
  "handler": { "name": "updateWorkspaceHandler", "file": "src/api/workspace/workspace.handler.ts", "line": 120,
               "uses": [{ "kind": "controller", "name": "updateWorkspace", "file": "src/api/workspace/workspace.controller.ts" }] },
  "hints": ["id-in-path"],
  "files": ["..."], "hash": "2c6b81b26c5a6878",
  "status": "checked",
  "checks": [
    { "class": "authz-membership", "result": "ok",
      "evidence": "workspace.repository.ts:88 UPDATE ... WHERE id = $1 AND EXISTS (membership role in owner/editor)" },
    { "class": "idor-parent-scope", "result": "n/a", "evidence": "single id, it is the parent" },
    { "class": "mass-assignment", "result": "candidate", "evidence": "workspace.validator.ts:40 accepts owner_id" }
  ]
}
```

Unit statuses: `planned` → `in_progress` → `checked` | `skipped` (with `skipReason`) | `carried` (unchanged since a
previous run that checked it). Check results: `ok`, `candidate`, `n/a`; `evidence` is a `file:line` plus what that
line shows.

## Hunter output (hunt-<group>.json)

```json
{
  "group": "workspace",
  "units": [{ "id": "PUT /api/workspaces/:id", "status": "checked", "checks": [ ... ] }],
  "candidates": [
    {
      "fingerprint": "workspace|mass-assignment|owner_id accepted on update",
      "class": "mass-assignment",
      "title": "Workspace update accepts owner_id from the body",
      "units": ["PUT /api/workspaces/:id", "mcp:workspace_update"],
      "locations": [{ "file": "src/api/workspace/workspace.validator.ts", "line": 40 }],
      "evidence": "UpdateWorkspaceSchema has owner_id: k.string().uuid().optional(); repository spreads it into SET",
      "attack": "editor sends PUT /api/workspaces/<id> {owner_id: <self>} and becomes owner"
    }
  ]
}
```

## Finding (findings.json)

```json
{
  "version": 1,
  "findings": [
    {
      "id": "F-001",
      "fingerprint": "workspace|mass-assignment|owner_id accepted on update",
      "class": "mass-assignment",
      "title": "Workspace update accepts owner_id from the body",
      "status": "confirmed",
      "severity": "high",
      "units": ["PUT /api/workspaces/:id", "mcp:workspace_update"],
      "locations": [{ "file": "src/api/workspace/workspace.validator.ts", "line": 40 }],
      "evidence": "...",
      "attack": "editor sends PUT /api/workspaces/<id> {owner_id: <self>}; repository line 88 writes it",
      "impact": "any editor takes ownership of the workspace and can delete it",
      "fix": "drop owner_id from UpdateWorkspaceSchema; ownership transfer gets its own owner-only endpoint",
      "test": "editor PUT with owner_id -> 422 and owner unchanged",
      "verification": { "verdict": "survived", "reasoning": "no layer strips owner_id: validator passes it, controller and repository forward it" }
    }
  ]
}
```

| status | when | required besides the common fields | severity |
| --- | --- | --- | --- |
| `confirmed` | the verifier tried to disprove it and couldn't | `attack`, `impact`, `fix`, `verification.verdict = "survived"`, `verification.reasoning` | required |
| `needs_validation` | plausible, but something only a run or a person can settle | `openQuestion` | none |
| `hardening` | another layer already blocks the attack; this one is still worth adding | `fix` | none |
| `rejected` | the verifier found what blocks it | `rejectionReason`, `verification.reasoning` | none |

Common fields: `id` (`F-001`...), `fingerprint` (stable across runs: resource | class | root cause), `class`,
`title`, `units` (ledger ids), `locations` (`file` relative to the project, existing `line`), `evidence`.

Severity: `critical` = anonymous or any user reads/writes other tenants' data or takes over accounts; `high` = a
member escalates (role, ownership) or reaches another workspace's data with an id; `medium` = abuse that needs
effort or has limited reach (no limiter on a costly public endpoint, info leak of internal ids); `low` = everything
else that is still a real boundary failure.
